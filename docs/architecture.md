# Architecture

The project is a server-rendered Next.js App Router application using TypeScript, PostgreSQL, Prisma for typed access, and a checked-in SQL migration for deterministic schema provisioning. Public routes query published database content at request time so changes are immediately visible to crawlers; database-backed content is never stored in a local JSON file. Zod validates request data at the server boundary. Admin sessions are random opaque tokens stored only as SHA-256 hashes, held in HTTP-only, SameSite cookies; passwords use bcrypt cost 12.

The schema is normalized around applications, platforms, categories, releases, support, legal content, media, pages, messages, settings, analytics, and audit logs. Application-owned content (release notes, app-scoped support, app-scoped legal documents and media associations) cascades when an application is deleted. A category deletion sets application category references to null. Platforms are restricted while assigned. Media assets are restricted while linked; unlinked assets remain for reuse/cleanup. Contact messages detach from a deleted application. Admin users are restricted from role deletion; sessions cascade with their user.

Media uses an adapter interface with local filesystem storage for development, S3-compatible storage, or ImgBB hosting. ImgBB uploads use a server-side API key and store the returned image URL and deletion link; hosted images are public. Local storage is refused in production unless an explicit override is set. Container deployments should use managed PostgreSQL and durable media storage. This design trades static generation speed for immediate content freshness and straightforward editorial consistency.
